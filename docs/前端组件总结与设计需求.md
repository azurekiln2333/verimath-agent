# 小艺 A2A 数理统计学习导师 · 前端组件总结与设计需求文档

> 面向 UI/UX 设计师的组件盘点与设计输入文档。
> 用途：设计师据此对全部组件重新设计视觉规范，工程侧据此对齐新设计稿完成实现。
> 对应代码：`app/panel_html.py`（页面与样式）、`app/static/statlib.js`（统计计算）、`app/static/plot.js`（绘图原语）、`app/static/widgets.js`（可视化组件）、`app/artifacts/spec.py`（组件参数契约）。

---

## 1. 产品概述

**产品**：数学与统计学习导师智能体（对接小艺 A2A 开放平台）。
**目标用户**：理学专业大学生、考研/竞赛学生。
**核心交互**：学生用自然语言提问（如"两组成绩比较应该用什么统计方法？"），智能体流式回答（SSE），并在回答中**按需内嵌可交互统计可视化组件**——学生拖动滑块即可观察"参数变化如何改变分布/检验结论/功效"，把抽象统计概念变成可操作的直觉。

**产品四大教学支柱**（每个支柱对应一组可视化组件）：
| 教学目标 | 对应组件 |
|---|---|
| 分布长什么样、参数怎么影响形状 | distribution_explorer |
| p 值到底是什么、假设检验怎么判 | hypothesis_test |
| 中心极限定理为什么成立 | sampling_distribution |
| 别只看 p 值：置信区间、功效、效应量 | confidence_interval / power_curve / effect_size |

**产品形态**：当前为本地 Web 调试面板（桌面三栏），未来迁移为小艺 App 内嵌 WebView / 移动端 H5。设计需同时考虑桌面与移动两端。

## 4. 组件详细规格

> 每个组件含：用途 / 数据输入 / 视觉要素 / 交互 / 状态 / 无障碍 / 响应式。
> "数据输入"即后端 spec 契约（`app/artifacts/spec.py`），设计师无需改契约，只需按其提供视觉。

### V1 分布探索器 distribution_explorer

- **用途**：回答"这个分布长什么样？参数变了会怎样？"
- **图型**：单曲线（pdf 或 cdf）或双曲线（both：实线 pdf + 虚线缩放 cdf），可含阴影区间（shade_from→shade_to）、可标记竖线（mark_x）。
- **分布族**：normal（μ, σ）/ t（df）/ χ²（df）/ F（dfn, dfd）/ beta（a, b）/ 指数（scale）/ 二项（n, p）/ 泊松（λ）。
  - 连续分布：平滑曲线 + 曲线下面积；
  - 离散分布（二项/泊松）：柱状条（pmf），竖线标 k。
- **滑块**：按分布族变化（见 3.3 表格），默认全部可调，支持 `interactive` 白名单只开放指定参数。
- **视觉要点**：坐标轴标签随 show 切换（"概率密度"↔"累积概率"）；双图模式需图例（"密度 pdf" + "累积 cdf（已缩放）"）；阴影区使用主题主色半透明填充。
- **无障碍**：canvas `aria-label` 携带标题+说明；滑块必须有 `aria-label`。

### V2 假设检验视图 hypothesis_test

- **用途**：讲 p 值含义、讲某次具体检验结论。"p 值是 H0 为真的概率"这种误解最怕看见这张图。
- **图型**：零分布曲线（z/t/χ²/F 四种）+ **红色半透明拒绝域**（α 尾部）+ **主色 p 值面积** + 观测统计量竖线 + 临界值竖线。
- **信息标注**（图内文字，需设计师定样式）：
  - 右上角结论行：`p = 0.031 < α = 0.05`（拒绝时红色 / 不拒绝时绿色）；
  - 第二行：`在 α 水平下拒绝 H₀` 或 `不能拒绝 H₀（≠ H₀ 成立）`；
  - 竖线标签：`临界值 ±1.960`、`观测值 2.341`。
- **滑块**：α（0.001–0.2）、观测统计量（范围随检验类型自适应）、t 检验额外加 df。
- **语义色需求**：拒绝域 vs p 值面积必须可区分（当前：warn 红 20% 透明 vs 主色 16% 透明）——**颜色对比度是本组件最要紧的设计点**。
- **无障碍**：aria-label 含统计量/p 值/结论三段式描述。

### V3 抽样分布模拟 sampling_distribution

- **用途**：中心极限定理可视化——"总体不正态也没关系，样本均值逼近正态"。
- **图型**：左右双图（组件级要求保持双图结构）：
  - 左：**总体直方图**（灰），形状来自 population（normal/uniform/expon/bimodal/skewed）；
  - 右：**统计量抽样分布直方图**（主色）+ 正态参考虚线（强调色），图例"模拟结果 / 正态参考曲线"。
- **统计量**：mean / median / variance / max（x 轴标签随之变化）。
- **滑块**：样本量 n（1–200）、重复抽样次数（100–5000）、随机种子（1–999）。
- **图下教学注记**（.artifact-note 样式，下同）：展示实际标准误 vs 理论标准误 SE=1/√n，点明"左图不变、右图随 n 变钟形"。
- **交互约束**：n 增大右图即时收窄（重算为前端本地毫秒级）；种子滑块用于"换个数看是否巧合"。

### V4 置信区间覆盖率 confidence_interval

- **用途**：纠正"95% CI 意味着参数有 95% 概率落在里面"的误解。
- **图型**：N 条水平区间横条（竖排，每条 = 一次重复实验），**真值竖线**贯穿，**未覆盖真值的区间用警示色加粗**；图顶标注覆盖率：`覆盖 47/50 = 94.0%（名义 95.0%）`。
- **滑块**：样本量 n、置信水平（0.5–0.995）、重复次数（10–200）、随机种子。
- **视觉要点**：覆盖（主色）vs 未覆盖（警示色，线宽更粗）必须一眼可分；区间条数 ≤200，随次数动态增高（canvas 高度 = 60 + n×7px，上限 460px）。
- **图下注记**：解释"造区间的程序"与"某一条区间"的区别。
- **无障碍**：aria-label 报告 n 次实验中的覆盖率。

### V5 功效曲线 power_curve

- **用途**：功效（1−β）与样本量/效应量/α 的四角关系；估算"需要多少样本"。
- **图型**：x 轴三种模式——每组样本量 n（默认）/ 效应量 Cohen's d / α；y 轴恒为功效 (0–1)；
  - 主曲线（实线，主色 2.2px）+ 参考线：目标功效水平线（默认 0.8，灰色）+ α 水平虚线（警示色）；
  - 可选对比曲线（compare 数组，虚线，多色序列色板）；
  - n 模式且效应量已知时：竖线标注"需 n = X"（达到目标功效所需样本量）。
- **滑块**：α + 效应量 + n（根据 x_axis 自动隐藏对应项）。
- **图内标注**：当前配置下功效读数 `n = 30 时功效 0.632`（右上角）。
- **教学注记**：无固定注记文案，跟随 spec。

### V6 散点回归 scatter_regression

- **用途**：相关与回归；"相关不等于因果"；外推不可靠。
- **图型**：散点（主色圆点）+ 回归线（强调色）+ 可选项：CI 置信带（灰色虚线，外宽内窄体现外推风险）、残差线（红色细竖线）。
- **图内标注**：左上角信息条（白底半透明）`ŷ = 0.412 + 1.203x   r = 0.891   R² = 0.794`。
- **交互**：无滑块（数据由用户提供/场景数据驱动）。
- **图下注记**：R² 的局限、残差图比 R² 更能暴露问题。
- **约束**：最少 3 个数据点，x/y 等长；坐标轴标签由 spec 提供（x_label/y_label）。

### V7 数据分布图 data_plot

- **用途**：拿到数据先看分布（做检验前的习惯养成）。
- **三种图型**：
  - **histogram 直方图**（默认）：密度纵轴，可叠加正态参考虚线（overlay_normal），多组时半透明叠放 + 图例；唯一带滑块的模式：分箱数（自动建议 Sturges 规则）。
  - **box 箱线图**：每组一行，盒 + 须 + 中位数线 + **均值点**（与中位数区分，偏态数据的关键差异）+ 离群点（警示色，同组色透明填充）。
  - **dot 点图**：每组一行，同值点上下抖动避免重叠。
- **数据**：最多 8 组 series（{label, values[]}）。
- **图下注记**：每组的 `n、均值、标准差` 摘要（组间用全角空格分隔）。
- **视觉要点**：多组配色走序列色板（6 色）；组标签在图左侧纵向排布。

### V8 效应量比较 effect_size

- **用途**：并排比较多项研究的效应量与其 CI——"显著但区间极宽"的信息量问题。
- **图型**：多条效应量 CI 横条（每项一行）+ **"无效应 = 0"参考竖虚线**；跨过参考线的区间用灰色（不显著），未跨过用主色（显著）。
- **图内标注**：每行左端组名标签。
- **图下注记**：灰色 = 跨过无效应线；区间宽度反映精度。
- **约束**：最多 20 项，每项必须 label/estimate/ci_low/ci_high 且 estimate 落在区间内。
- **交互**：无滑块。

### F6 ArtifactCard 可视化卡片（所有 V 组件的统一容器）

每个可视化组件都包在一个统一卡片里，结构固定：

```
┌───────────────────────────────────┐
│ 标题（13px 粗体）                  │
│ 说明 caption（12px 灰，自动换行）  │
├───────────────────────────────────┤
│ 画布（canvas，响应式 100% 宽）     │
├───────────────────────────────────┤
│ 教学注记 note（11.5px 浅灰底）     │
├───────────────────────────────────┤
│ 参数滑块组（标签+数值+滑条，可选） │
│ [恢复初始参数]                    │
└───────────────────────────────────┘
```

- 关键交互约束：**图表与文字答案解耦**——流式回答期间 token 持续重写文字气泡，图必须挂在独立容器不受影响；meta 事件到达即先画图（学生可以在答案流完前就开始拖动）。
- 图渲染失败：卡片内显示降级提示条（警示色），文字答案不受影响，同时静默上报渲染失败原因。
- 无障碍：滑块滚动微调需焦点/悬停判定；所有 canvas 有等价文字描述。

## 5. 现有视觉规范提取（供设计师作基线，可推翻但需覆盖）

### 5.1 色彩

| 语义 | 当前值 | 用途 |
|---|---|---|
| 背景 bg | `#f6f7f9` | 页面底色 |
| 表面 surface | `#ffffff` | 卡片/面板 |
| 次级表面 | `#f0f3f6` | 胶囊底、分块底 |
| 墨色 ink | `#17202a` | 主文字、曲线 |
| 次要文字 muted | `#687381` | 说明、元信息 |
| 边框 line | `#d7dde4` | 卡片描边、分割线 |
| **主色 accent** | `#256f5f`（深青绿） | 品牌、主曲线、选中态、填充底 `rgba(37,111,95,.16)` |
| **强调色 accent2** | `#b45f35`（陶土橙） | 对比曲线、回归线、cdf 虚线 |
| 警示 warn | `#9a3412`（深红） | 拒绝域、未覆盖区间、错误 |
| 成功 ok | `#166534`（绿） | 结论通过、状态正常 |
| 网格 | `rgba(120,132,145,.18)` | 坐标网格线 |
| 序列色板 SERIES | `#256f5f #b45f35 #3b5b8c #7a5195 #94722a #2f7f8f` | 多组数据（最多 6 色循环） |

> 设计要点：accent/accent2 承担"主数据 vs 参照/对比"的语义对；warn/ok 承担"拒绝/通过"结论语义。**重新设计时建议保留语义结构，可改色值**（需通过无障碍对比度校验，文字对背景 ≥ 4.5:1，大面积着色 ≥ 3:1）。

### 5.2 字体

- 系统字体栈：`system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`；代码/公式：`ui-monospace, Consolas, monospace`。
- 字阶：正文 14px/1.55；卡片标题 13px；注记 11.5–12px；气泡 Markdown 标题 15–20px。
- 数字使用 tabular-nums（等宽数字，滑块读数不跳动）。

### 5.3 其他

- 圆角 8px（卡片）、999px（胶囊/开关）、12px（ArtifactCard）。
- 阴影：卡片 `0 2px 10px rgba(22,32,42,.04)`；浮层 `0 12px 28px rgba(22,32,42,.08)`。
- 公式渲染：KaTeX（独立公式带浅色底 + 边框块）。
- 响应式断点：1100 / 760 / 420。
- 动画：打字点 pulse 1s；开关滑动 0.15s；尊重 `prefers-reduced-motion`。

## 6. 设计交付需求（给设计师的 Checklist）

1. **覆盖范围**：4 个框架组件 + 8 个通用控件 + 8 个可视化组件 + ArtifactCard 容器，共 21 个组件。
2. **每个组件交付物**：正常态/悬停/焦点/禁用（+ 图表典型数据样例截图 2–3 组）。
3. **图表专项**：8 类图各给 2 种数据密度样例（稀疏/密集）；标注图层级规范（标题、轴标签、图例、图内标注、竖线标签的字体/颜色/位置规则）。
4. **语义色规范**：主色/强调色/警示色/成功色/序列色板在浅色背景上的完整使用规则；若支持深色模式，给出暗色全套色板（plot.js 注释声明"颜色走 CSS 自定义属性，跟随主题"——**架构已支持暗色，设计需补齐**）。
5. **响应式**：桌面三栏 → 平板 → 手机单列的组件适配规则（图表在窄屏如何处理：缩放？滚动？双图变上下堆叠？）。
6. **无障碍**：全部文字-背景对比度达标；滑块/按钮/开关的 aria 命名建议；图表信息的文字替代方案（当前用 aria-label 摘要，是否升级为"可展开的数据表"是产品决策点）。
7. **动效规范**：打字动画、流式文字、图重绘过渡、卡片进入动画的时间曲线。
8. **设计稿格式**：Figma（推荐）/ 可标注的 PNG + 组件属性表；色板/字阶/间距以 Design Token 形式给出（CSS 变量），便于工程侧落地。

## 8. 架构约束（设计落地须知）

1. **零外部依赖**：现有前端为纯手写 Canvas 绘图 + 本地化 vendor（markdown-it / KaTeX / DOMPurify），可注入沙箱 CSP `connect-src 'none'`。重设计**不要求引入图表库**，CSS/切图/Canvas 实现均可接受，但不要假设可加载 CDN 资源。
2. **契约稳定**：8 类组件的参数契约（spec.py）与模型提示词绑定，视觉重设计**不改动数据契约**。
3. **降级优先**：任何图渲染失败都必须有优雅降级路径（提示条 + 文字答案完整）。
4. **性能**：滑块拖动 = 本地毫秒级重绘，不做防抖但也不能引入动画帧之外的额外开销；高 DPI 需清晰（当前按 devicePixelRatio 放大）。
